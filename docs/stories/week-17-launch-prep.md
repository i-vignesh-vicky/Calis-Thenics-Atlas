- Outcome: A polished launch package and readiness summary
- Focus: Launch assets, QA, and communication materials
- Status: Todo

# TASK-066 · Prepare Launch Assets and Support Links
Epic: Launch
Estimate: 3 hrs
Priority: High
Status: Todo

## Objective
Assemble the launch-facing assets and support information for the MVP.

## Implementation Steps
- [ ] Add the privacy, support, and contact links in the release docs and app metadata.
- [ ] Gather screenshots, app descriptions, and release copy drafts.
- [ ] Place the launch files in a single agreed location so they are easy to review.

- The launch assets should be complete enough for a release owner to review without chasing down information.
- Keep a simple record of where each asset lives so handoff is straightforward.

- [ ] Confirm the release copy and support links are readable and not placeholder content.

## Documentation
- [ ] Document the launch asset folder and the release copy expectations.

## Acceptance Criteria
- [ ] Launch assets are prepared and easy to locate.
- [ ] Support and privacy links are present.
- [ ] Release copy is ready for review.

- Launch assets
- Support links
- Release copy draft

# TASK-067 · Run Final QA on Critical Flows
Epic: Launch
Estimate: 4 hrs
Priority: High
Status: Todo

## Objective
Validate the MVP-critical flows just before launch.

## Implementation Steps
- [ ] Run the core auth, profile, workout, and settings flows manually or with smoke tests.
- [ ] Record any bugs or regressions discovered and note their severity.
- [ ] Mark the flows as verified, deferred, or blocked with a short note.

## Technical Notes
- Final QA should be focused on the most valuable user journeys rather than every feature edge case.
- Keep the bug log simple and useful for the final launch decision.

## Tests
- [ ] Run the critical flow checks and record the outcome.
- [ ] Ensure the smoke tests pass before launch sign-off.

## Documentation
- [ ] Document the QA results and the launch decision record.

## Acceptance Criteria
- [ ] The critical flows are tested before launch.
- [ ] Any issues are captured with clear notes.
- [ ] The QA results are documented for sign-off.

## Deliverables
- Final QA checklist
- Issue log
- Launch sign-off notes

# TASK-068 · Add Release Sign-Off Notes
Epic: Launch
Estimate: 3 hrs
Priority: Medium
Status: Todo

## Objective
Create a concise launch decision document for the MVP.

## Implementation Steps
- [ ] Summarize what is included in the release and what is deferred.
- [ ] List known limitations and follow-up work for the first post-launch iteration.
- [ ] Add a final approval check with owner, date, and release decision.

## Technical Notes
- The sign-off note should be clear enough for a founder or release owner to make a launch decision quickly.
- Keep the list of limitations explicit so expectations are grounded in the shipped scope.

## Tests
- [ ] Review the sign-off note for completeness and clarity.
- [ ] Ensure it captures all pending launch questions.

## Documentation
- [ ] Place the sign-off note in the release documentation folder.

## Acceptance Criteria
- [ ] A release sign-off note exists.
- [ ] Known issues are documented clearly.
- [ ] It is ready for the founder or release owner.

## Deliverables
- Release sign-off note
- Known limitations list
- Launch decision record
